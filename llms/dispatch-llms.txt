# Dispatch

> Dispatch (Dispatch Technologies) is a service-orchestration platform for enterprises that fulfil work through networks of independent contractors and third-party service providers — manufacturer warranty, home and property claims, retail, franchise and proptech. Its public REST API v3 exposes jobs, customers, organizations, appointments, users, sources, brands, survey responses and a composite work order to job sources and service enterprises. Generated by API Evangelist from Dispatch's own public documentation; Dispatch does not publish an llms.txt.

Key facts for an agent working with this API:

- Base URL (production): `https://api.dispatch.me` — core API, versioned in the path at `/v3/`.
- Base URL (sandbox): `https://api-sandbox.dispatch.me` — a full separate environment; test and live are separated by hostname, not by key prefix.
- Files are a separate host: `https://files-api.dispatch.me` (`/v1/datafiles`), sandbox `https://files-api-sandbox.dispatch.me`.
- Auth is OAuth 2.0 bearer. `POST /v3/oauth/token` with `client_credentials` (job sources) or `password` (an individual service provider), and `refresh_token` to renew. Tokens are temporary — handle 401 by re-authenticating.
- There is no OAuth scope vocabulary. Authorization is an account-level ACL negotiated with a Dispatch account manager. Credentials are not self-service.
- Paging is `limit` / `offset`, with a maximum `limit` of 100. Filtering is a nested query object: `?filter[status_eq]=scheduled&filter[job_id_eq]=123`, with `_eq`, `_not_eq`, `_in`, `_null`, `_contains`, `_gt`, `_gteq`, `_lt`, `_lteq` predicates.
- Responses wrap payloads in a resource-named root key: `{"job": {...}}` for one, `{"jobs": [...]}` for many.
- There is no idempotency key. Use the caller-supplied `external_ids` array to correlate and deduplicate customers and organizations instead; a retried write is not guaranteed safe.
- Errors are plain HTTP statuses (400/401/403/404/422/429/500/503), not RFC 9457 problem+json. 422 carries per-field validation detail in the body.
- Start with the work order (`POST /v3/work_orders`) unless you need direct access to the underlying objects — it creates the job, customer, organization and appointment windows in one call.
- Scheduling an appointment moves its parent job to `scheduled`. Cancelling a job cancels all of its child appointments.
- Locations are supported in the United States and Canada only.
- Webhooks exist but are not self-service — they are configured by an account manager, and Dispatch publishes no event catalog or payload schema. Poll the list endpoints with timestamp filters otherwise.

## APIs

- [Dispatch REST API v3](https://github.com/DispatchMe/v3-api-docs): Jobs, customers, organizations, appointments, users, sources, brands, survey responses and work orders.
- [Dispatch Files API v1](https://github.com/DispatchMe/v3-api-docs/blob/master/source/index.html.md#files-photos): Upload and retrieve photos and other files associated with a job.
